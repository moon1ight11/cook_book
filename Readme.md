# CookBook API
Backend-сервис для кулинарного сообщества с возможностью создания, поиска и управления рецептами, а также ролевой моделью доступа (пользователь/администратор).

## Возможности
-  **Аутентификация** — JWT-токены в HttpOnly cookies с поддержкой refresh-токенов
- **Управление пользователями** — регистрация, вход, обновление профиля, удаление
- **Управление рецептами** — CRUD операции, поиск по тегам, фильтрация по сложности и названию
- **Ролевая модель** — разделение на обычных пользователей (Basic) и администраторов (Admin)
- **Пагинация** — постраничный вывод списка рецептов с настраиваемым размером страницы
- **Кэширование** — самодельный in-memory кэш с TTL для хранения рецептов и результатов поиска по тегам
- **Логирование** — структурированное логирование с ротацией файлов
- **Контейнеризация** — Docker и Docker Compose для локальной разработки
- **CI/CD** — автоматическая сборка и публикация образа в GitHub Container Registry

## Технологии
- **Основной язык**  — Go 1.25
- **HTTP-фреймворк** — Echo
- **Основная база данных** — MongoDB
- **Аутентификация** — JWT
- **Хэширование паролей** — bcrypt
- **Конфигурация** - Viper
- **Кэширование** — In-memory cache
- **Логирование** — Slog + lumberjack (ротация логов)
- **Контейнеризация** — Docker, GitHub Container Registry (GHCR)
- **CI/CD** — GitHub Actions (автоматическая сборка при push)
- **Архитектура** — Clean Architecture

## Особенности реализации
### Транзакции и целостность данных
- При создании пользователя автоматически устанавливаются базовые настройки
- При удалении пользователя каскадно удаляются все его рецепты
- Индексы в MongoDB создаются автоматически при запуске для оптимизации запросов

## Кэширование
Реализован самодельный in-memory кэш с фоновой очисткой:
    Стратегия — cache-aside (данные сначала ищутся в кэше)
    TTL — настраиваемое время жизни записи (по умолчанию 5 минут)
    Фоновая очистка — горутина, которая каждую минуту удаляет просроченные записи
    Кэшируются — отдельные рецепты по ID и результаты поиска по тегам
    Инвалидация — автоматическое удаление из кэша при обновлении или удалении рецепта

## Graceful Shutdown
При получении сигнала завершения (SIGINT, SIGTERM) сервер:
    Прекращает принимать новые соединения
    Ожидает завершения активных запросов (таймаут 10 секунд)
    Корректно закрывает соединение с MongoDB
    Останавливает горутину очистки токенов
    Дожидается завершения всех фоновых задач

Очистка просроченных refresh-токенов
    Фоновая горутина запускается при старте сервера
    Каждые 24 часа проверяет и удаляет просроченные refresh-токены из БД
    Graceful остановка через контекст и sync.WaitGroup

## Логирование
- Структурированное логирование с уровнями DEBUG, INFO, WARN, ERROR
- Запись логов в файл с ротацией (lumberjack)
- Единый формат с атрибутами key=value

## Безопасность
Пароли хэшируются с помощью bcrypt (cost factor = 10)
- JWT-токены: access (в HttpOnly cookie) и refresh (в теле ответа)
- Refresh-токены хранятся в БД в захэшированном виде (SHA-256)
- Валидация email через регулярное выражение
- При обновлении email или пароля — автоматическая смена всех токенов
- CORS-настройки для безопасного взаимодействия с фронтендом
- Role-based middleware для защиты админских эндпоинтов

## Индексы базы данных
Автоматическое создание индексов при старте:
- Рецепты: owner_id, tags, created_at (по убыванию)
- Пользователи: email (уникальный)

## CI/CD
GitHub Actions настроен на:
- Автоматическую сборку Docker-образа при ручном запуске (workflow_dispatch)
- Публикацию образа в GitHub Container Registry (ghcr.io)
- Тегирование образа как latest
