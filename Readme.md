## Возможности
-  **Аутентификация** — JWT-токены в HttpOnly cookies с поддержкой refresh-токенов
- **Управление пользователями** — регистрация, вход, обновление профиля, удаление
- **Управление рецептами** — CRUD операции, поиск по тегам, фильтрация по сложности и названию
- **Ролевая модель** — разделение на обычных пользователей (Basic) и администраторов (Admin)
- **Пагинация** — постраничный вывод списка рецептов с настраиваемым размером страницы
- **Кэширование** — самодельный in-memory кэш с TTL для хранения рецептов и результатов поиска по тегам
- **Мониторинг** — экспорт метрик в Prometheus и визуализация в Grafana
- **Логирование** — структурированное логирование с ротацией файлов
- **Контейнеризация** — Docker и Docker Compose для локальной разработки
- **CI/CD** — автоматическая сборка и публикация образа в GitHub Container Registry


## Технологический стек
- **Основной язык**  — Go 1.25
- **HTTP-фреймворк** — Echo
- **Основная база данных** — MongoDB 7.0 + Mongo Express
- **Аутентификация** — JWT
- **Безопасность:** SHA-256 для хэширования refresh-токенов
- **Тестирование:** testify (assert + mock)
- **Хэширование паролей** — bcrypt
- **Конфигурация** — Viper
- **Кэширование** — In-memory cache (собственная реализация)
- **Метрики** — Prometheus + Grafana 
- **Логирование** — Slog + lumberjack (ротация логов)
- **Документация:** OpenAPI 3.0
- **Контейнеризация** — Docker, GitHub Container Registry (GHCR)
- **CI/CD** — GitHub Actions
- **Архитектура** — Clean Architecture


## Архитектура
Проект построен на принципах **Clean Architecture** с четким разделением на слои:
- **Handler / Delivery** — HTTP-обработчики (Echo).
- **Service / Usecase** — бизнес-логика приложения.
- **Repository** — слой доступа к данным (MongoDB).
- **Domain** — модели, не зависящие от внешних фреймворков.


## Быстрый старт
### Предварительные требования
- Go 1.25+
- Docker и Docker Compose
- MongoDB 7.0 (опционально, если используется Docker)

### Локальный запуск
1. **Клонировать репозиторий**
2. **Настроить конфигурацию**
```bash
    cp config.example.yml config.yml
    # В соответствии с config.example.yaml, создайте файл config.yaml, указав необходимые параметры
```
3. **Запустить инфраструктуру**
```bash
    docker-compose up -d
```
4. **Запустить приложение**
```bash
    go run cmd/main.go
```
Сервер будет доступен на http://localhost:8080.

### Проверка работоспособности
```bash
    curl http://localhost:8080/health
    #Ответ: OK
```

## Особенности реализации
### Кэширование
Реализован самодельный in-memory кэш с фоновой очисткой:
- **Стратегия:** cache-aside (данные сначала ищутся в кэше).
- **TTL:** настраиваемое время жизни записи (по умолчанию 5 минут).
- **Фоновая очистка:** горутина, которая с заданным интервалом удаляет просроченные записи.
- **Кэшируются:** отдельные рецепты по ID и результаты поиска по тегам.
- **Инвалидация:** автоматическое удаление из кэша при обновлении или удалении рецепта.

### Логирование
- Структурированное логирование с уровнями `DEBUG`, `INFO`, `WARN`, `ERROR`.
- Запись логов в файл с автоматической ротацией (lumberjack).
- Единый формат сообщений с атрибутами `key=value`.

### Graceful Shutdown
При получении сигнала завершения (`SIGINT`, `SIGTERM`) сервер:
1. Прекращает принимать новые соединения.
2. Ожидает завершения активных запросов (таймаут 10 секунд).
3. Корректно закрывает соединение с MongoDB.
4. Останавливает горутину очистки просроченных refresh-токенов.
5. Дожидается завершения всех фоновых задач (`sync.WaitGroup`).

### Очистка просроченных refresh-токенов
- Фоновая горутина запускается при старте сервера.
- Раз в 24 часа проверяет и удаляет просроченные refresh-токены из БД.
- Graceful остановка через контекст и `sync.WaitGroup`.

### Индексы базы данных
При старте приложения автоматически создаются следующие индексы:
- **Рецепты:** `owner_id`, `tags`, `created_at` (по убыванию).
- **Пользователи:** `email` (уникальный).

### Транзакции и целостность данных
- При создании пользователя автоматически устанавливаются базовые настройки
- При удалении пользователя каскадно удаляются все его рецепты
- Все операции с данными выполняются атомарно

### Безопасность
- Пароли хэшируются с помощью **bcrypt** (cost factor = 10).
- **JWT-токены:** `access` хранится в HttpOnly cookie, `refresh` передается в теле ответа.
- Refresh-токены хранятся в БД в захэшированном виде (SHA-256).
- Сравнение токенов через `subtle.ConstantTimeCompare` (защита от timing-атак)
- Валидация email через регулярное выражение.
- При обновлении email или пароля — автоматическая смена всех токенов.
- Настроены политики **CORS** для безопасного взаимодействия с фронтендом.
- **Role-based middleware** для защиты административных эндпоинтов.

## Мониторинг
Сервис экспортирует метрики для Prometheus (`/metrics`):
- `http_requests_total` — счетчик HTTP-запросов (method, endpoint, status)
- `http_request_duration_seconds` — гистограмма длительности запросов
- `http_requests_in_flight` — текущее количество обрабатываемых запросов
- `app_operations_total` — счетчик бизнес-операций (SignUp, CreateRecipe...)
- `app_errors_total` — счетчик ошибок по типам (bad_request, forbidden, internal)
- `go_goroutines_count` — количество горутин
Готовый дашборд для Grafana: `metrics/dashboard.json`

- Публикацию образа в **GitHub Container Registry** (`ghcr.io`).
- Тегирование образа как `latest`.
